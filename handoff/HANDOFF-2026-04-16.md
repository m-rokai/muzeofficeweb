## 1. Codex review → 3 fixes

Ran `/codex:review` in the background against the working tree. Codex flagged three issues, all real and all now fixed in commit `a368978`.

### Issue 1 — Dedicated Desk price contradiction (P2)

**File**: `app/page.tsx:318, 325`

Homepage advertised Dedicated Desk at `$350/month`. But the source of truth (`lib/data/services.ts:102-124`) prices:
- **Hot Desk**: $350/month
- **Dedicated Desk**: $399/month

Visitors comparing homepage → `/las-vegas-coworking` would see contradictory pricing.

**Fix**: two edits in `app/page.tsx` — the copy paragraph above the pricing grid ("dedicated desks from $350/mo" → `$399/mo`) and the pricing card itself (`price: "$350"` → `"$399"`).

### Issue 2 — Sitewide trailing-slash canonicalization regression (P2)

**File**: `next.config.ts:94-95`

`skipTrailingSlashRedirect: true` had been added with a comment claiming explicit redirect rules would handle slash variants directly. They don't — the only slash-aware logic in the proxy handles the `www` host. Every other route (`/contact/`, `/blog/some-post/`, every city-service page) would serve under both a trailing- and non-trailing-slash URL, reintroducing duplicate crawlable URLs and undoing canonicalization work.

**Fix**: deleted the flag. Next.js's default `/foo/` → `/foo` redirect is restored.

### Issue 3 — Footer FAQ link points to nothing (P3)

**Files**: `lib/data/navigation.ts:40`, `components/marketing/faq-section.tsx:37`

Footer navigation had `{ label: "FAQ", href: "/#faq" }`, but `<FAQSection>` rendered a `<section>` with no `id`. Clicking FAQ from any footer on the site just reloaded the homepage without scrolling.

**Fix**: added `id="faq"` to the section wrapper.

### Verification

- Local `npm run build` and `bun run build` both passed with 100 static pages.
- `tsc --noEmit` and `eslint` both clean (per Codex reviewer's sandboxed checks).

## 2. GitHub + Vercel CI/CD integration

Project had been deploying via `vercel deploy --prod` CLI only — no git-linked repo. Migrated to push-to-deploy.

### What happened

1. **`gh auth status`** confirmed logged in as `m-rokai`.
2. **Attempted `gh repo create muzeoffice-web --source=. --push`** — this *succeeded* but created a **new duplicate repo** at `m-rokai/muzeoffice-web` because I didn't check for an existing one first.
3. User pointed out the canonical repo was `m-rokai/muzeofficeweb` (no hyphen, created 2026-04-08).
4. Couldn't delete the duplicate — token lacks `delete_repo` scope. Logged as cleanup for the user.
5. Repointed local `origin` to `github.com/m-rokai/muzeofficeweb.git` and pushed.
6. **Vercel's Git integration auto-triggered a build** → it failed with 15 `Module not found` errors.
7. **Root cause**: the initial `f542574` commit and the `a368978` fix commit only contained a handful of files. The working directory had ~300 untracked files (components, lib, content, public assets, drafts, handoff docs) that had never been added. Vercel cloned an incomplete repo and couldn't resolve `@/components/layout/section`, `@/lib/data/services`, `@/components/marketing/animate`, etc.
8. **Remedy**: `git add -A` → `git commit` (2f2e625, 296 files, +28636 LOC) → `git push`. New Git-triggered deploy succeeded (`muzeoffice-atfd0ssha.vercel.app`, Ready, 42s build).

- **Preview vs Production**: the Git-triggered deploy landed as *Preview*, not Production. Check Vercel Dashboard → Settings → Git and confirm `master` is set as the Production Branch so pushes go live on muzeoffice.com automatically.
